# 0x0048F090 is a constructor, not a plain method

The 38-byte body at 0x0048F090 (ILT 0x00011AD1) is the default constructor
`??0Gen_00490100@@QAE@XZ`, replacing the ledger's earlier spelling
`?bfmeInitCCF@BfmeThingCCF@@QAEPAU1@XZ`. The prior row matched every byte but
named the wrong member kind, which is exactly what blocked the tail repair of
`?dup_00C23607@@YAXXZ` (InGameUI constructor unwind funclet): a plain method
cannot be the callee of a `new` expression, so the InGameUI constructor had to
emulate retail's allocation with a guard object, and that guard compiles to a
different cleanup funclet than retail's.

## Constructor evidence

- The InGameUI constructor 0x0044B800 (matched, same ledger) allocates
  `0x24` bytes with `??2@YAPAXI@Z` (ILT 0x00881F30) at 0x0044BAA5 and, at
  0x0044BABB, calls 0x0048F090 through ILT 0x00011AD1 with `mov ecx, eax`
  on the freshly allocated pointer: the MSVC 7.1 `new`-expression pattern
  (`push 0x24; call ??2; add esp,4; mov [esp+10h],eax; cmp eax,ebx; je;
  mov ecx,eax; call <ctor>; jmp; xor eax,eax`).
- The body returns `this` in EAX (`mov eax, esi` at +0x22), as MSVC
  constructors do; the caller stores that result straight into the member at
  +0x81C (0x0044BAC5: `mov [esi+0x81c], eax`).
- The unwind funclet for that same state, at retail 0x00C2361F
  (`mov eax,[ebp-14h]; push eax; call ??3@YAXPAX@Z; pop ecx; ret`), is the
  delete-on-throw cleanup MSVC emits only for a `new` expression whose
  callee is a constructor.
- The body installs vtable 0x010F9AAC, recorded in dir32_addresses.csv as
  `??_7Gen_00490100@@6B@`, whose class is therefore Gen_00490100; the matched
  complete destructor `??1Gen_00490100@@UAE@XZ` at 0x00490100
  (Bfme5BodyVectorDtors.cpp) names the same class. A default constructor of
  that class is decorated `??0Gen_00490100@@QAE@XZ`; no new name is invented,
  the class name was already established by the matched destructor row.

## Extent

The old and new claims cover the identical range 0x0048F090/38B; the bytes
are unchanged and re-verified by the add_match build. The source file
game/GameEngine/Source/Common/BfmeConv577.cpp now defines the constructor
under its corrected identity.
